# Типовые проблемы

Сначала определите границу отказа: запуск контейнера, HTTPS, SSH или доступ к файлам по SMB.
Для существующего production-стека команды ниже выполняются из каталога установки.
Для встроенного Samba-узла добавьте `-f docker-compose.samba.yml` перед подкомандой.

## Контейнеры и HTTPS

```bash
docker compose --env-file deploy/production/.env -f docker-compose.production.yml ps
docker compose --env-file deploy/production/.env -f docker-compose.production.yml logs --tail=100 web nginx
```

| Симптом | Что проверить |
| --- | --- |
| Образ не скачивается | Конкретный тег из Releases или digest, доступ к Docker Hub. Наличие JAR на хосте для готового образа не требуется. |
| `web` не запускается | Ошибку в логах, наличие и тип файла `known_hosts`, права UID 10001. |
| `nginx` не запускается | Пути TLS-файлов, соответствие ключа сертификату, доступ `PROXY_UID` к ключу, ненулевые UID/GID. |
| Контейнеры healthy, браузер не открывает страницу | Bind-адрес, HTTPS-порт, firewall, DNS, имя и доверие TLS-сертификату. `127.0.0.1` доступен только с Docker-хоста или через настроенный туннель. |
| HTTPS работает, но SSH-вход не проходит | Это другая граница. Проверьте SSH-адрес и порт с точки зрения контейнера панели. |

Подготовка файлов и ожидаемые состояния описаны в [Production Compose](production.md#existing-server).

## SSH-вход

| Симптом | Действие |
| --- | --- |
| Неизвестный ключ сервера | Независимо сверить fingerprint и добавить точный host/port в `known_hosts`. |
| Ключ сервера изменился | Прекратить попытки и установить причину. Подтверждённая переустановка сервера и подмена ключа требуют разного реагирования. |
| Сетевой отказ или неверные реквизиты | Проверить DNS, маршрут, порт, SSH-пользователя и разрешённый способ входа. Общее сообщение не позволяет определить точную причину. |
| В форме указан `localhost` | Панель подключается к своему контейнеру. Указать адрес Samba-сервера, доступный из контейнера, либо `samba-node` для встроенного узла. |
| Отказ входа по ключу | Проверить, что передан приватный ключ нужной пары без passphrase, а публичный установлен нужному SSH-пользователю. Не публиковать содержимое приватного ключа. |
| «Сессия истекла» при работе | Повторить вход вручную. Закрытие вкладки не считается выходом; см. [срок сессии](sessions.md). |

Для образов до исправления обработки login HTTP 401 неверные реквизиты могли показываться
как «Сессия истекла». Исправление входит в `v0.14.0`.
Порядок обновления доверия SSH — в [инструкции по ключам](ssh-host-keys.md#changed-key).
Не заменяйте доверенный ключ для исправления сетевой ошибки или пароля.

## SSH работает, операции панели — нет

В версиях с панелью готовности откройте **Обзор → Проверить готовность**.
Отказ отдельной команды не доказывает причину: это могут быть права, отсутствие утилиты
или ошибка конфигурации. Подсказка в отчёте указывает следующий шаг.
Полные административные права и реальный SMB-доступ отчётом не проверяются.
[Состав проверок](server-setup.md#server-readiness).

Если Samba-клиент видит ресурс, но не открывает его, используйте
[проверку доступа к ресурсу](access-diagnostics.md): настройки Samba и права Linux проверяются
совместно. `testparm` проверяет конфигурацию, а не права конкретного пользователя.
Не используйте рекурсивное открытие прав всем пользователям как способ диагностики.

## Резервные копии

| Симптом | Что это означает |
| --- | --- |
| В UI нет кнопки создания копии | Проверьте версию образа: кнопка возвращена после `v0.14.0`. API создания копии существовал и ранее. |
| Список недоступен | Это не подтверждение отсутствия копий. Проверить SSH, наличие каталога backup, права чтения/прохода SSH-пользователя и утилиты `find`/`ls`. Затем нажать «Повторить загрузку списка»; форма сохранится. |
| Копия создана, список не обновился | Не повторять создание только из-за ошибки перечитывания. Повторить загрузку списка и проверить сервер. |
| Восстановление не подтверждено | Проверить `smb.conf` и службу перед повтором: запрос мог остановиться на проверке, позднем этапе либо потерять ответ. |

[Создание, восстановление и границы backup](configuration-backups.md).

## Что приложить к сообщению об ошибке

Укажите версию или digest панели, ОС Samba-сервера, Docker/Compose, способ подключения,
действие, ожидаемый и фактический результат, HTTP-статус и время отказа.
Приложите только относящиеся к ошибке строки логов после проверки содержимого.
Пароли, приватные ключи, cookie, токены и пользовательские файлы не прикладывайте.
