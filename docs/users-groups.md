# Пользователи и группы

Панель управляет локальными учётными записями подключённого Linux/Samba-сервера.
Это не учётные записи самой панели и не управление пользователями контроллера AD.
[Проверка доменного сценария](https://github.com/AndreyJVM/sambryx/issues/64) выделена отдельно.

## Три разных назначения учётной записи

| Учётная запись | Назначение |
| --- | --- |
| SSH-администратор | Вход в панель и выполнение серверных команд по sudo policy |
| Linux-пользователь | UID/GID, группы и права файловой системы |
| Samba-пользователь | Аутентификация файлового клиента по SMB |

Наличие Linux-пользователя не означает, что у него есть Samba-пароль или доступ к ресурсу.
Пароль Samba не заменяет SSH-реквизиты администратора.

## Создание пользователя

В разделе **Пользователи** откройте форму добавления, задайте логин, отображаемое имя
и пароль. Если отображаемое имя не задано, используется логин.

Приложение последовательно:

1. Создаёт Linux-пользователя с домашним каталогом и shell `/bin/bash`.
2. Устанавливает Linux-пароль.
3. Добавляет Samba-учётную запись с тем же паролем и включает её.

Используйте новый логин: форма не является механизмом подключения существующего
Linux-пользователя к Samba. Для обычного логина используйте строчные латинские буквы,
цифры, `_`, `.` и `-`, начиная с буквы или `_`; максимум 32 символа.
Защищённые системные учётные записи изменять через API запрещено.

Созданная запись — полноценный Linux-пользователь, а не изолированная SMB-идентичность.
Возможность её SSH-входа зависит от политики SSH-сервера; sudo-права ей автоматически
не выдаются. После создания отдельно настройте группу и ресурс.

## Смена пароля

Кнопка смены пароля обновляет **Linux- и Samba-пароль** выбранного пользователя.
Это две последовательные операции, а не транзакция. При ошибке проверьте оба способа
аутентификации перед повтором. Новые пароли не должны содержать переводы строк;
текущая реализация удаляет пробелы по краям пароля.

## Группы и префикс

В разделе **Группы** создайте, например, `accounting`. При стандартном
`samba.group.prefix=smb_` на сервере создаётся **`smb_accounting`**.
В интерфейсе группы префикс скрывается; отображаются только группы с настроенным префиксом.
Остальные системные группы этим списком не представлены.

| Место использования | Значение при стандартном префиксе |
| --- | --- |
| Создание и управление группой в UI | `accounting` |
| Команды Linux | `smb_accounting` |
| Поле ресурса `valid users` | `@smb_accounting` |
| Поле ресурса `force group` | `smb_accounting` |

Не добавляйте `smb_` в имя при создании через UI: иначе получится двойной префикс.
Подсказки полей ресурсов сейчас используют сокращённые имена; проверяйте фактическое имя
и при необходимости вводите его вручную.

## Добавление и удаление участников

Откройте добавление участника у группы, выберите пользователя или введите несколько
логинов через запятую. Добавление изменяет дополнительное членство Linux-пользователя.
Несколько логинов обрабатываются отдельными запросами: часть может добавиться до ошибки.

Удаление участника убирает его из дополнительной группы, а не удаляет учётную запись.
Основная группа пользователя может не отражаться в списке участников UI.
Для проверки на сервере:

```bash
id alice
getent group smb_accounting
```

Это диагностические команды, а не команды изменения прав. Проверять их нужно
на Samba-сервере. После изменения членства используйте новое SMB-подключение:
уже открытая сессия может сохранять прежнюю идентичность и права.

## Удаление

**Пользователь:** удаление затрагивает Samba-запись и Linux-пользователя;
Linux-команда `userdel -r` также удаляет его домашний каталог и почтовый spool.
До подтверждения сохраните нужные данные и проверьте владельцев файлов.
Файлы вне домашнего каталога могут остаться с числовым UID удалённого пользователя.
После операции проверьте обе базы: ошибка удаления Samba-записи не останавливает
текущую попытку удаления Linux-пользователя.

**Группа:** удаляется Linux-группа с настроенным префиксом. Ссылки на неё в `valid users`,
`force group` и владельцах каталогов автоматически не исправляются. Основная группа
существующего пользователя может не удалиться.

Backup `smb.conf` не восстанавливает пользователей, пароли, SID, группы, владельцев
или удалённый домашний каталог. Для этих данных требуется отдельная резервная копия.
