# Резервные копии конфигурации

Раздел **Глобальные настройки → Резервные копии конфига** позволяет вручную сохранить
текущий `smb.conf` на подключённом Samba-сервере и восстановить сохранённую версию.
Раздел виден и до создания первой копии.

## Чтение списка

«Резервные копии не найдены» означает, что каталог доступен и перечисление завершилось
успешно без копий. Отсутствующий или неподготовленный каталог, отказ доступа, сбой SSH,
таймаут и непригодный ответ показываются как недоступность списка.

При ошибке старые записи скрываются. Нажмите **Повторить загрузку списка**, чтобы снова
прочитать только список: форма и её несохранённые значения сохраняются. Повтор не создаёт
копию, не восстанавливает конфигурацию и не перезапускает Samba. Автоматического повтора нет.

Для диагностики проверьте SSH-соединение, наличие настроенного каталога backup, права
чтения и прохода SSH-пользователя на каталог и родительские каталоги, доступность `find`
и `ls`. Чтение списка не использует sudo. Отсутствующий каталог автоматически не создаётся;
его подготовку и права следует согласовать с администратором. Непригодная запись также
делает весь список недоступным: частичный список не выдаётся за полный. Не передавайте
пароли, ключи, сырые команды или полный stderr в сообщениях об ошибке.

## Создание копии

Нажмите **Создать резервную копию**. Панель сохраняет конфигурацию, которая сейчас находится
на сервере. Несохранённые изменения формы в копию не входят; форма не применяется,
служба Samba не перезапускается. После успешного ответа обновляется только список копий,
значения формы сохраняются.

Во время запроса повторное создание, применение конфигурации и восстановление заблокированы.
Хранятся до 10 последних копий; создание новой может удалить более старые копии.
Это копии конфигурации Samba, а не файлов общих ресурсов, учётных записей, групп или ACL.
Для восстановления сервера после аварии требуется отдельная резервная копия этих данных.

Если создание не подтверждено, проверьте список и состояние сервера перед повтором:
ошибка ответа или очистки старых копий не доказывает, что файл не был создан.
Если копия создана, но обновление списка не удалось, интерфейс показывает оба результата
раздельно. Недоступный список не означает отсутствие резервных копий.

## Сравнение перед восстановлением

У выбранной копии нажмите **Сравнить**. Направление: **текущий серверный smb.conf →
выбранная копия**. Знак `−` показывает удаляемую строку текущего файла, знак `+` —
добавляемую строку копии. Номер относится к соответствующему файлу. Имя выбранной копии
видно над результатом. Отсутствие перевода строки в конце файла отмечается отдельно.
Одинаковые файлы имеют явный результат; ошибка чтения не означает равенства.

Сравниваются только буквальные тексты двух файлов. Несохранённая форма, содержимое
`include` и внешние файлы не читаются. Комментарии, порядок, пробелы и переводы строк
учитываются; это не семантическая проверка Samba. HTML-подобные строки выводятся как текст.

Операция доступна только после аутентификации. Она не создаёт копий, не меняет
конфигурацию, права или службы. Восстановление остаётся отдельным действием с подтверждением.
Сравнение не блокирует серверные файлы и не фиксирует состояние до восстановления:
файлы могут измениться даже между двумя чтениями. Перед восстановлением можно повторить
сравнение; показанный результат относится только к выполненному чтению.

Принимаются только имена формата `smb.conf.backup_YYYYMMDD_HHMMSS` с необязательным
суффиксом `_1`–`_99`; путь пользователя не принимается. Символьные ссылки и нестандартные
файлы отклоняются при проверке. Для одного файла допускаются до 256 KiB UTF-8 и 1000 строк,
для одного приложения — два одновременных сравнения. Ответ содержит максимум 2000 изменённых
строк; чтение ограничено первыми 256 KiB + 1 байтом и таймаутом 10 секунд на файл.
Превышение лимита, NUL, символ замены Unicode (включая повреждённое декодирование), отказ
чтения, занятость или сбой SSH дают безопасную ошибку без частичного diff и сырых диагностик.
Содержимое файлов не записывается в operational logs; автоматических повторов нет.

Нужны доступ к метаданным файлов для SSH-пользователя, `bash`, `timeout`, `head` и существующее
разрешение `sudo -n cat`. Новые sudo-права не выдаются, привилегированный shell не запускается.
Если доступа нет, согласуйте его с администратором вне операции сравнения.

## Требования SSH-пользователя

Root-вход и привилегированный shell не нужны. Создание копии повышает права только
для отдельных файловых команд: временный файл создаётся в каталоге backup, заполняется,
затем публикуется через hard link без замены существующей записи. При совпадении имени
выбирается суффикс. Правила sudo описаны в [подготовке сервера](server-setup.md).
Если удаление временного файла не удалось, операция возвращает ошибку, хотя завершённая
копия уже могла появиться. Администратору нужно проверить копию и остаточный временный файл.

## Восстановление

Выберите нужный файл и нажмите **Восстановить**. Диалог показывает имя копии и последствия.
Сервер проверяет её через `testparm`, сохраняет текущую конфигурацию, заменяет `smb.conf`
и перезапускает `smbd`. Возможен кратковременный перерыв обслуживания.
Успешное восстановление перечитывает форму; несохранённые изменения теряются.

Отказ проверки копии запрещает её установку. Ошибка на более позднем этапе или потеря ответа
не гарантируют автоматического отката: проверьте конфигурацию и состояние Samba перед повтором.
Корректный синтаксис не гарантирует доступ пользователей к ресурсам; при отказе используйте
[проверку доступа](access-diagnostics.md).
