# Создание личной папки

При подготовке первого частного ресурса можно создать новую папку с явно выбранными
локальными владельцем и группой и правами `0700` через панель. Это отдельное действие
в диалоге **Обзор → Новая папка**. Сохранение ресурса по-прежнему не назначает права
или владельцев существующим каталогам.

## Перед созданием

На Samba-сервере должны существовать локальные пользователь и группа. Их записи
проверяются через `getent -s files passwd` и `getent -s files group`; UID и GID должны
быть положительными. Доменные имена, группы с `@` и несколько пользователей здесь
не поддерживаются. Владельца нельзя автоматически вывести из `valid users`.

Родитель должен уже существовать внутри настроенного разрешённого корня.
После разрешения ссылок физический путь также должен быть в разрешённых корнях.
Вся физическая цепочка родителя до `/` должна принадлежать UID 0 и не разрешать
запись группе или остальным. Например, `/srv/samba` с `root:root 0755` подходит.
Папка, принадлежащая обычному пользователю, или родитель с `0775` не подходит.
Это ограничение защищает новую запись от подмены между файловыми командами.
Настройку родителей выполняет администратор сервера; панель их не меняет.

SSH-администратору нужны Bash, GNU coreutils, glibc `getent` с выбором базы `files`
и неинтерактивный sudo для `mkdir`, `chmod`, `chown`. Shell работает без повышения
привилегий. `sudo bash`, `sudo sh`, Python от root и `sudo ALL` не требуются.
Существующий setup-профиль уже разрешает эти три утилиты; новая операция не меняет
sudoers автоматически. Совместимость с другими ОС отдельно не подтверждена.

## Действия в панели

1. Создайте локального пользователя и включите его Samba-учётную запись.
2. В форме ресурса откройте **Обзор**, перейдите в подходящего родителя и нажмите
   **Новая папка**.
3. Введите новое имя, включите **Подготовить личную папку (0700)**, явно заполните
   локального владельца и группу. Режим фиксирован: читать, записывать и входить
   может только владелец.
4. Нажмите **Сохранить**. Проверьте путь, владельца, группу и `0700` в отдельном
   подтверждении, затем нажмите **Создать личную папку**.
5. Выберите созданную папку в качестве пути ресурса. Укажите нужного пользователя
   в `valid users`, выключите гостевой доступ и разрешите запись, если она нужна.
6. Сохраните ресурс. Проверьте mkdir, загрузку, скачивание и содержимое реальным
   SMB-клиентом от разрешённого пользователя; отдельно проверьте отказ постороннему.

Маски `create mask` и `directory mask` относятся к новым объектам Samba и не
подготавливают существующую папку. Назначение владельца и `0700` не гарантирует
доступ по SMB: влияют родители, ACL, учётная запись, конфигурация и серверные политики.
Для общих каталогов с несколькими пользователями этот workflow не предназначен.

## Команды и границы изменений

После проверок операция выполняет только следующие привилегированные действия
для одного нового абсолютного пути, например `/srv/samba/alice`:

```bash
sudo -n mkdir -m 0700 -- /srv/samba/alice
sudo -n chmod 00700 -- /srv/samba/alice
sudo -n chown --no-dereference --from=0 -- 1001:1002 /srv/samba/alice
```

UID и GID берутся из проверенных локальных записей. Пятизначный режим `00700`
снимает в том числе унаследованный setgid каталога. Для индивидуальной sudo policy
администратор должен разрешить именно эти утилиты, аргументы и предназначенные
пути; не расширяйте права до shell или `ALL`. Неограниченные аргументы файловых
утилит дают широкие полномочия вне панели и не являются ограниченной policy.

Нет рекурсии, `mkdir -p`, изменения родителей или существующих данных. Занятое имя,
включая каталог, файл и висячую ссылку, приводит к отказу до chmod/chown.
Ссылка в родительском пути допустима только к разрешённому доверенному родителю;
новая запись ссылкой быть не может. Защита предполагает доверенного root и обычную
семантику Linux filesystem, без злонамеренного root или изменения mount namespace.

Операция не является транзакцией. При отказе chmod/chown или потере SSH-ответа новая
папка может остаться. UI сообщает об ошибке; автоматического удаления или отката
нет. Проверьте состояние на сервере до повтора. Повтор с тем же именем не изменяет
оставшуюся папку. Обычная **Новая папка** без выбора подготовки тоже использует
исключительное создание и не делает chmod существующей записи.
