# Общие папки

Ресурс Samba — именованная секция в `smb.conf`, указывающая на каталог Samba-сервера.
Путь клиента, например `\\fileserver\documents`, отличается от серверного пути
`/srv/samba/documents`. Контейнер панели не хранит копию этого каталога.

## Перед созданием

1. Проверьте, что подключён нужный сервер и есть актуальная копия конфигурации.
2. Подготовьте [пользователей и группы](users-groups.md).
3. Выберите отдельный каталог. По умолчанию файловые операции ограничены корнями
   `/mnt`, `/media`, `/srv`, `/data`, `/home`; настройка — `samba.security.allowed-roots`.
4. Для существующего каталога проверьте владельца, группу и права до сохранения.
   Копия `smb.conf` не сохраняет права и владельцев файлов.

## Создание ресурса

Откройте **Общие папки**, нажмите кнопку создания, заполните форму и сохраните.

| Поле | Значение и действие |
| --- | --- |
| Имя | Имя ресурса для клиента. Допускаются латинские буквы, цифры, `_` и `-`; имя должно быть уникальным без учёта регистра. |
| Путь | Абсолютный путь на Samba-сервере, например `/srv/samba/documents`. Отсутствующий каталог создаётся. |
| Только чтение | Запрещает запись по правилам Samba, с учётом `write list`. Права Linux также должны допускать нужные операции. |
| Гостевой доступ | Разрешает гостевой сценарий Samba; это не безопасная замена именованным пользователям. Результат зависит от глобальных настроек и прав гостевой учётной записи. |
| Видимость | Управляет отображением ресурса при просмотре списка. Скрытие не запрещает обращение по известному имени. |
| Разрешённые пользователи | `valid users`: имена пользователей и `@` перед реальным именем группы, например `alice, @smb_accounting`. Пустое поле не означает запрет всем. |
| Маски файлов и каталогов | `create mask` и `directory mask`. Ограничивают объекты, создаваемые через Samba; сохранение ресурса не применяет эти маски к каталогу или существующим файлам. |

Для нового частного ресурса оставьте гостевой доступ выключенным и явно задайте
нужную идентичность. После сохранения проверьте доступ с SMB-клиента разрешённого
и постороннего пользователя — одного успешного `testparm` недостаточно.

## Что меняет сохранение

Описанное ниже поведение относится к текущему `master` после `v0.15.0` и ещё не выпущено.
В `v0.15.0` сохранение ресурса применяет `chmod` к каталогу и может рекурсивно менять
владельца по полям ресурса. Для этой версии учитывайте эти последствия до сохранения.

Создание **и редактирование** ресурса выполняют следующие действия:

1. Проверка допустимости пути и создание отсутствующих каталогов через `mkdir -p`.
   Для существующего пути эта команда не служит признаком создания нового каталога.
2. Сохранение `smb.conf` с backup и проверкой `testparm`, затем перезапуск `smbd`.

Сохранение не выполняет `chmod` или `chown`: права и владельцы существующего каталога,
его подкаталогов и файлов сохраняются, в том числе при выборе другого существующего пути.
`valid users`, `force user`, `force group` и маски меняют только настройки Samba.

Новые каталоги получают владельца и права по правилам сервера при выполнении `sudo mkdir -p`
(включая umask и наследование прав). Приложение не назначает им владельца из полей ресурса
и не гарантирует SMB-доступ. Подготовьте необходимые права средствами администрирования
сервера и проверьте доступ SMB-клиентом. Если подготовка пути завершилась ошибкой,
изменение конфигурации не продолжается. Созданные каталоги не удаляются при последующей
ошибке сохранения конфигурации.

## Дополнительные параметры

- `write list` — исключения для записи на уровне Samba, а не выдача прав Linux.
- `force user` / `force group` — идентичность файловых операций Samba; сохранение ресурса
  не назначает владельцев файлов. Не подставляйте SSH-администратора автоматически.
- `hosts allow` / `hosts deny` — ограничения клиентов по правилам Samba.
- `max connections` — ограничение числа подключений ресурса.

Подсказки полей ресурса используют полное Linux-имя группы, включая настроенный префикс.
Например, при стандартной настройке это `smb_accounting`, а не `accounting`.
В `valid users` нужна запись `@smb_accounting`, в `force group` — `smb_accounting` без `@`.
Префикс автоматически добавляется при управлении группами, но не при записи полей ресурса.

## Изменение и удаление

При редактировании имя существующего ресурса сохраняется; переименование отдельной
операцией не предусмотрено. Изменение пути переключает ресурс на другой каталог,
но не переносит файлы из старого.

Удаление ресурса убирает его секцию из `smb.conf` и перезапускает Samba.
Каталог и файлы не удаляются. Удаление файлов через файловый менеджер — отдельное действие.

При потере ответа или ошибке проверьте фактические каталог, конфигурацию и состояние
службы перед повтором. Для отказа открытия используйте [диагностику доступа](access-diagnostics.md).
Правила чтения и записи разобраны в [руководстве по правам](permissions.md).
